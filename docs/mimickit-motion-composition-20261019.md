# MimicKit 当前动作数据组成与跑步采样调整

本次在 CPU 上审计实际使用的原生动作文件，没有启动仿真或操作训练进程。

输入来源是 `data/motion_cap/amass_isaac/amass_isaac_run_upright_slim.pkl`，
已转换到官方 SMPL USD 配套的骨架。共 246 段、63,758 帧、2,117.07 秒
（35.28 分钟），帧率均为 30 FPS。单独的 standing 初始化文件没有混入训练。
数据源包含 KIT 185 段、BioMotionLab 23 段、ACCAD 22 段、Eyes Japan 8 段、
HumanEva 3 段、TotalCapture 3 段、SFU 2 段。

## 组成与抽样概率

| 类别 | 段数 | 唯一内容时长 | 原采样概率 | 新采样概率 |
| --- | ---: | ---: | ---: | ---: |
| 较快跑步候选：run 标签且根节点均速 ≥2 m/s | 21 | 32.90 秒 | 8.54% | 34.43% |
| 标注慢跑：HumanEva/SFU 的 jog/jogging | 3 | 38.87 秒 | 1.22% | 4.92% |
| 走路标签（包括 walking_run 录制编号） | 212 | 2,009.03 秒 | 86.18% | 57.92% |
| 走跑转换 | 2 | 8.90 秒 | 0.81% | 0.55% |
| 侧步 | 4 | 12.17 秒 | 1.63% | 1.09% |
| 走跳、跨跳 | 3 | 13.00 秒 | 1.22% | 0.82% |
| 其他或待确认 | 1 | 2.20 秒 | 0.41% | 0.27% |

类别依据名称与实测根节点速度，是候选分组，不是接触力或人工逐帧步态真值。
特别排除了 `walking_run08`、Running 目录下的侧步、walk-to-leap 等误判。
21 段较快跑步候选均速约 2.45–3.62 m/s；3 段标注慢跑均速约 1.02–1.54 m/s。
跑步候选多数只有约一秒，持续高速运动和走跑转换的多样性仍有限。

MimicKit 按 YAML 的相对权重抽片段，再在片段合法历史区间中均匀抽时间。
因此采样概率不能直接用唯一数据时长占比代替。

| 0.3 秒 AMP 历史窗口均速 | 原预计采样占比 | 新预计采样占比 |
| --- | ---: | ---: |
| <0.2 m/s | 25.44% | 17.10% |
| 0.2–0.8 m/s | 29.81% | 20.04% |
| 0.8–1.4 m/s | 29.82% | 22.81% |
| 1.4–2.0 m/s | 5.46% | 5.37% |
| 2.0–2.5 m/s | 0.72% | 1.74% |
| ≥2.5 m/s | 8.75% | 32.93% |

统计使用 XY 相邻帧路径长度而非起终点位移，历史长度为 10 帧/9 个间隔。
窗口比例由合法离散帧锚点近似连续时间抽样；速度阈值也是运动学代理，
不保证所有快速窗口都是跑步。

## 已实施的变更

默认列表改为 `data/mimickit/official_smpl/locomotion/motions-run6.yaml`。
24 段跑步/慢跑候选权重为 6，其他片段权重保留为 1。
这等价于每段总共保留 6 份、额外复制 5 份时的抽样概率。
列表仍只有 246 个唯一条目，原始 PKL、转换后姿态与原 `motions.yaml` 保留。
AMP 损失、对称损失、时间间隔和奖励系数没有因这次数据调整而修改。

权重同时影响判别器 demo 采样和参考状态初始化。当前进程已加载的数据分布
不会被文件修改即时改变，需要启动新进程。6 倍是对照实验起点，不是已验证最优值。

复现统计和列表：

```bash
python scripts/mimickit_amp/prepare_sampling.py --running_weight 6
```

默认 `prepare_motions.py` 也会在转换完成后生成该列表。相同输入可重复执行；
如果已有同名列表内容不同，脚本拒绝覆盖，需使用新的 `--output` 文件名。
逐片段指标、权重与来源哈希分别在输出列表旁的
`motions-run6.sampling.csv` 和 `motions-run6.sampling.json` 中。

从头训练自动使用新默认列表。从旧 checkpoint 接着训练时，需明确覆盖它
保存的动作列表：

```bash
./isaaclab.sh -p scripts/mimickit_amp/run.py \
  --mode train --amp_only --headless --device cuda:0 --num_envs 16384 \
  --checkpoint "$AMP_CKPT" \
  --motion_file data/mimickit/official_smpl/locomotion/motions-run6.yaml \
  --max_iterations 5000
```

此处仍遵循现有权重续训语义：网络/归一化参数保留，优化器与 replay 重新构建。
没有 `--motion_file` 时，checkpoint 保存的动作列表继续生效。

## 如何理解效果

原数据确实偏向走路，增加跑步采样是合理的受控实验。但复制或提高权重
没有增加独立动作多样性，也不能直接修复走路不流畅。
纯 AMP 未提供速度指令，不要求同一策略主动展示所有走跑模式；
仅靠四环境自由运动录像不能证明其跑步能力。
后续应分别检查持续跑步、走跑转换、足部接触和高速度任务表现，
不能保证本次重采样就能消除模式收缩或动作不自然。
